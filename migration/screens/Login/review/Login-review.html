  • "Forgot Password?" renders as captured and does nothing on click in the mock phase (Q1).
  • Login?In_IsFromResetPIN=True (not restored from the view cache): signOut() (session and local PIN), then the mock sign-in, which goes to PINRegister; the B2C round-trip is skipped as for the Login button (Q2, U4).
  • AppManager_Events renders as the empty captured widget and the Security Warning dialog stays closed; callback and device-awareness branches are not built (Q3). DeviceAwareness_InvalidDevice is an opaque constant (its identifier value is never written to the DOM), so any CallbackType in the mock leads to DelayedMessage_Show.
  • IsUnsupportedSystem = unsupported app version OR unsupported browser version (Q4): False on TST, True with ?mock=unsupported-browser (U16), which shows UnsupportedVersion_Wrapper instead of the welcome and buttons.
  • OnReady calls the shell's delayedMessageShow() (Q5, CR-Login-1); nothing is pending in the mock app.
  • "Login with UBT One" signs in at once as the mock user and the shell picks the destination (D3(a)/U4, shell auth.ts).
  • Static entity values large (UBT_Shape) and xxs (UBT_FontSize) are local constants taken from the captured classes (dom:40, dom:99) because the shared static entities do not have them.
  • Parity exemptions added for the capture-replay artifacts (Q6): CAPTURE-SVG-PRESERVEASPECTRATIO (ignoreSubtrees ubt-header-svg; the header SVG fills the LoginFlow page, so its mask leaves no pixels compared on this route: DOM, style and layout checks still run), CAPTURE-LOGO-REPLAY (logo subtree + WelcomeToConnect sizes and the buttons' offset), CAPTURE-LINK-HREF-CURSOR, CAPTURE-LOADING-BODYCLASS, CAPTURE-LOADING-TRANSITION.
