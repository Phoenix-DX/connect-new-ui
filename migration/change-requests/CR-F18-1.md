  `dx-bottom-bar-slider dx-bottom-bar-slider-appear` with `--dx-bottom-bar-transition-duration: undefinedms` in every
  default capture.

## Expected change
Two screen containers during a navigation with the runtime's class sequence and timing, `active-screen` on the new one,
the NavigationHandler events with the real `from`/`to`/`duration`, transitions carried from the compiled navigations,
POP reversing, and end states unchanged.

## Workaround in the route until applied
None.

## Resolution (foundation owner)
- Change (2026-10-16):
  - `shell/navigation/ScreenTransitionGroup.tsx` (new): TransitionGroup + CSSTransition + NH patch; one container per
    entry, new before old (mergeChildMappings), leaving screen keeps its DOM and a frozen LocationContext.
  - `shell/navigation/screenTransition.ts` (new): TransitionAnimation, createTransition, reverseTransition, class
    names, Root.getTransition with the goBack override, mergeChildMappings.
  - `transitionEvents.ts`: navigation events moved to the containers; first-screen pair stays in ScreenFrame; runtime
    TransitionEnd bus (`onceScreenTransitionEnd`).
  - `osNavigate.ts`: `transition` option (Default when absent), `useNavigateBack()(transition?)`.
  - Explicit transitions at the call sites listed above; `AppStart` and `useSignIn` redirects carry Default.
  - `app/screens.ts` (new) + `router.tsx`: a screen's code is loaded before its transition (runtime ScreenLoader);
    only the first screen suspends.
  - `StylesheetHost.tsx`: old sheets kept until TransitionEnd (CSSHelper).
  - The first screen no longer has the scaffold's static `slide-from-right-enter-done` (captures: none on a first load).
- Slider symptom: not a remove/re-append. The app-start BottomBarSlider_ForceRefresh appends the slider with
  `undefinedms`, so the `dx-bottom-bar-slider-appear` animation is invalid, `animationend` never fires and the class
  stays (as in every TST capture). The first real transition makes it valid: the appear keyframes play once over the
  translate. Later navigations translate. Kept 1:1.
- Tests: `screenTransition.test.ts`, `ScreenTransitionGroup.test.tsx`, updated `transitionEvents.test.tsx`,
  `StylesheetHost.test.tsx`; headless mid-transition check (scratchpad `f18/mid_transition.cjs`).
- Regression parity run on: all finished routes (F18 sweep), result in the F18 report.

## User decisions (2026-10-16)
- Kept 1:1 with TST (the user will compare on TST and report any visible difference): the first bottom-bar click after
  a load plays the slider's appear animation (`undefinedms` from BottomBarSlider_ForceRefresh); the reverse-direction
  class is set by the start event after the entering position is computed (direction lags one move); a screen re-entered
  while still leaving gets no `active-screen`.
- Reduced motion: kept as the original (no rule); decide in the production phase.
- Skill template updated (user OK): `scaffold_react_app.py` AppFrame comment marks the static container as a starting
  point (the file is written only when missing, so a re-scaffold never overwrote F18), and
  `assets/app-shell-spec-template.md` section 1 now lists screen transitions explicitly.
- Menu and ConnectShare re-stamped after the user's confirm (transition arguments only; parity 0).
