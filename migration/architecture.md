## Consistency rules (consistency_check.py)

- Required files per route: index.tsx; when the route has calls also api.ts, mocks.ts, types.ts
- Imports allowed from: the route's own folder, src/shared, src/shell, src/lib, src/components, src/mocks, src/vendor, and allowed packages
- NO-RAW-FETCH: server calls only through callAction in api.ts
- NO-BROWSER-STORAGE: no tokens or personal data in browser storage; use the shell's stores
- NO-ROUTE-CSS: the original CSS is global; routes add no CSS
- NO-INLINE-COLOR: visual differences are fixed in markup, not inline styles (inline CSS variables from the capture are fine)
- NO-RAW-HTML: HTML from data goes through the shared sanitizer component
- NO-WIRE-IN-COMPONENTS: components see domain types only; wire shapes stay in api.ts/mocks.ts
- NO-CONSOLE: no debug output left in routes

## ADR log

### ADR-1: Target platform: web / PWA only (no store app) (accepted)
- Context: The React app replaces the OutSystems mobile app (Cordova, 21 native plugins in the survey: FCM push, Crashlytics, TouchId, Barcode, Location, SocialSharing, File/FileTransfer/FileViewer, InAppBrowser, PrivacyScreen, ScreenOrientation, Keyboard, LocalNotification, AppLauncher, EventfulDeeplinks, AndroidAppLinks). Options were web first + Capacitor later, Capacitor from the foundation, or web/PWA only.
- Decision: Web / PWA only (user, 2026-10-14). UI stays HTML/CSS 1:1. Native features go behind adapters in src/lib/device with web equivalents decided per feature in the behaviour inventory (extras group C).
- Consequences: No app-store build. Per-feature web equivalents to decide: push (Web Push; iOS only for installed PWAs, 16.4+), biometric unlock (WebAuthn), barcode (camera + JS library), share (Web Share API), files (download/open), in-app browser (new tab), deep links (URLs + manifest), crash reporting (web monitoring). PrivacyScreen, orientation lock and keyboard control have no full web equivalent. Service worker (Workbox) comes with production integration, not in the mock phase.
- accepted by user 2026-10-14T13:14:02

### ADR-2: Baseline: current stable dependency versions before scaffolding (accepted)

Exact versions are chosen from the npm registry, checked together in a scratch install (typecheck, build, tests), listed for the user, then pinned with dep add.
- Consequences: The foundation owner adapts scaffold_react_app.py output to the new majors once (router, MSW, test setup). Version list needs the user's acceptance before dep add.

### ADR-8: Bookmark sync replaces the local bookmarks in one IndexedDB transaction (accepted)
- Context: SynchBookmarks / SynchBookmarksC2 (app start, via Sync_Info_GetMain) run DeleteAll then CreateOrUpdate as two IndexedDB transactions in the original (OutSystems.js deleteAll -> executeTransaction). A screen that reads LocalBookmark between the two steps sees no bookmark (menu shows Bookmark instead of Unmark). On TST the first screen reads before the sync starts; in the clone the first screen loads right after the GetUserInformation step, so its read lands inside the sync (HouseholdDetails default parity, F4a 2026-10-15). Known original race: known-original-bugs.md B5.
- Decision: Keep the clone's entityService.replaceAll: delete and re-create the bookmark rows in one transaction (app/src/shell/localEntities/entities.ts:230, localBookmarks.ts:200-225). Recommended by the orchestrator; auto-accepted under the user's auto mode (2026-10-15 16:59) and listed for the user's review.
- Consequences: Deviation from the 1:1 rule (bugs included): a read during the sync now sees either the old or the new rows, never none. No visible change on TST timing. Revert = two transactions again plus a timing exemption on HouseholdDetails default.
- accepted by user 2026-10-15T19:47:02

### ADR-10: Personal data in IndexedDB: documented exception to stack tokens (accepted)
- Context: Stack tokens: never in browser storage. The original (TST) keeps notes, bookmarks, search history, recent searches and Orbit local entities in IndexedDB; the clone does the same (app/src/shell/localEntities, ADR-8). The user decided P10 on 2026-10-16: keep it as the original.
- Decision: Client entities stay in IndexedDB as in the original. Tokens, PIN and identity secrets are never stored in browser storage (unchanged). When installed, call navigator.storage.persist(); after an eviction, re-sync from the server; clear all local entities on logout. Only the shell stores touch browser storage (rule NO-BROWSER-STORAGE unchanged for routes).
- Consequences: Personal data at rest on the device, as today in TST; the privacy notice must mention it. Safari may evict data of non-installed sites; every screen must work after an eviction.
- accepted by user 2026-10-16T16:38:39

### ADR-14: Production service worker served at TST's worker URL /UBTConnect/pwaServiceWorker.js (cutover handover) (accepted)
- Context: PWA fact F2 (user, 2026-10-17): TST registers /UBTConnect/pwaServiceWorker.js on scope /UBTConnect/. It is cache-first for every screen path from its precache, and old caches are deleted only by a newer worker (migration/knowledge/pwa-tst-service-worker.md). Browsers re-check the registered script URL; if it answers 404 after cutover, devices keep the cached OutSystems app. P15 decided a same-origin cutover with a service-worker handover. Options: (A) serve our own worker at that URL; (B) a kill switch at that URL, then the new index.html registers /sw.js.
- Decision: Option A (user, 2026-10-17): production builds serve the app service worker at /UBTConnect/pwaServiceWorker.js with scope /UBTConnect/, instead of /sw.js. Browsers update the existing registration in place on their next update check. On activate, the worker deletes the OutSystems caches (names starting with UBTConnect-).
- Consequences: Production SW URL and output path change (src/pwa/swRoutes.ts SW_URL, build/pwa.ts, src/sw/sw.ts activate cleanup, tests, docs/guides/pwa.md). The URL must keep answering from cutover on (never 404). The worker file stays under /UBTConnect/, not at the root of the origin shared with ConnectMobile. The demo build is not covered by this ADR (own host). Implementation is phase 5 work.
