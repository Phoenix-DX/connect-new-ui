## Consistency rules (consistency_check.py)

- Required files per route: index.tsx; when the route has calls also api.ts, mocks.ts, types.ts
- Imports allowed from: the route's own folder, src/shared, src/shell, src/lib, src/components, src/mocks, src/vendor, and allowed packages
- NO-RAW-FETCH: server calls only through callAction in api.ts
- NO-BROWSER-STORAGE: no tokens or personal data in browser storage; use the shell's stores
- NO-ROUTE-CSS: the original CSS is global; routes add no CSS
- NO-INLINE-COLOR: visual differences are fixed in markup, not inline styles (inline CSS variables from the capture are fine)
- NO-RAW-HTML: HTML from data goes through the shared sanitizer component
- NO-WIRE-IN-COMPONENTS: components see domain types only; wire shapes stay in api.ts/mocks.ts
- NO-CONSOLE: no debug output left in routes

## ADR log

### ADR-1: Target platform: web / PWA only (no store app) (accepted)
- Context: The React app replaces the OutSystems mobile app (Cordova, 21 native plugins in the survey: FCM push, Crashlytics, TouchId, Barcode, Location, SocialSharing, File/FileTransfer/FileViewer, InAppBrowser, PrivacyScreen, ScreenOrientation, Keyboard, LocalNotification, AppLauncher, EventfulDeeplinks, AndroidAppLinks). Options were web first + Capacitor later, Capacitor from the foundation, or web/PWA only.
- Decision: Web / PWA only (user, 2026-10-14). UI stays HTML/CSS 1:1. Native features go behind adapters in src/lib/device with web equivalents decided per feature in the behaviour inventory (extras group C).
- Consequences: No app-store build. Per-feature web equivalents to decide: push (Web Push; iOS only for installed PWAs, 16.4+), biometric unlock (WebAuthn), barcode (camera + JS library), share (Web Share API), files (download/open), in-app browser (new tab), deep links (URLs + manifest), crash reporting (web monitoring). PrivacyScreen, orientation lock and keyboard control have no full web equivalent. Service worker (Workbox) comes with production integration, not in the mock phase.
- accepted by user 2026-10-14T13:14:02

### ADR-2: Baseline: current stable dependency versions before scaffolding (accepted)
- Context: Scaffold pins 2024 versions (React 18.3, Vite 5.4, React Router 6.26, TS 5.6, MSW 2.4, Node 20 which is end of life since 2026-04-30). The app replaces production; nothing is built yet.
- Decision: Upgrade the baseline before scaffolding (user, 2026-10-14: React 19, Node 24 LTS, current stable Vite, React Router, TypeScript, MSW, test and lint tools). Exact versions are chosen from the npm registry, checked together in a scratch install (typecheck, build, tests), listed for the user, then pinned with dep add.
- Consequences: The foundation owner adapts scaffold_react_app.py output to the new majors once (router, MSW, test setup). Version list needs the user's acceptance before dep add.
- accepted by user 2026-10-14T13:14:02

### ADR-8: Bookmark sync replaces the local bookmarks in one IndexedDB transaction (accepted)
- Context: SynchBookmarks / SynchBookmarksC2 (app start, via Sync_Info_GetMain) run DeleteAll then CreateOrUpdate as two IndexedDB transactions in the original (OutSystems.js deleteAll -> executeTransaction). A screen that reads LocalBookmark between the two steps sees no bookmark (menu shows Bookmark instead of Unmark). On TST the first screen reads before the sync starts; in the clone the first screen loads right after the GetUserInformation step, so its read lands inside the sync (HouseholdDetails default parity, F4a 2026-10-15). Known original race: known-original-bugs.md B5.
- Decision: Keep the clone's entityService.replaceAll: delete and re-create the bookmark rows in one transaction (app/src/shell/localEntities/entities.ts:230, localBookmarks.ts:200-225). Recommended by the orchestrator; auto-accepted under the user's auto mode (2026-10-15 16:59) and listed for the user's review.
- Consequences: Deviation from the 1:1 rule (bugs included): a read during the sync now sees either the old or the new rows, never none. No visible change on TST timing. Revert = two transactions again plus a timing exemption on HouseholdDetails default.
- accepted by user 2026-10-15T19:47:02

### ADR-10: Personal data in IndexedDB: documented exception to stack tokens (accepted)
- Context: Stack tokens: never in browser storage. The original (TST) keeps notes, bookmarks, search history, recent searches and Orbit local entities in IndexedDB; the clone does the same (app/src/shell/localEntities, ADR-8). The user decided P10 on 2026-10-16: keep it as the original.
- Decision: Client entities stay in IndexedDB as in the original. Tokens, PIN and identity secrets are never stored in browser storage (unchanged). When installed, call navigator.storage.persist(); after an eviction, re-sync from the server; clear all local entities on logout. Only the shell stores touch browser storage (rule NO-BROWSER-STORAGE unchanged for routes).

### ADR-15: Target front-end architecture (refactor-plan-v2) (accepted)
- Context: The React app passes parity with OutSystems on all 64 routes, but its folders follow the OutSystems structure (`screens/`, `shared/`, `shell/`). Plan v2 §7 counts 71 files that call `callAction` outside `api/`, 50 users of `getClientVar` and a 1,077-line component file. The goal is code that a team can keep in production, with the same UI and calls as the original. The user approved `app/docs/architecture/refactor-plan-v2.md` on 2026-10-22, with R1 to R8 as recommended and D1 to D4 of the draft (§9). Auto decisions Q1 to Q4 of the same day, accepted under the user's delegation, changed the tools (`migration/refactor/auto-decisions-2026-10-22.md`).
- Decision: Adopt the target architecture of `app/docs/architecture/refactor-plan-v2.md` §2 and §3 for `app/src/`. Plan v2 holds the full text; this ADR lists the decisions and points to the sections.
  - Terms (§2.1): a page renders one route, in `pages/<Route>/<Route>Page.tsx`, and does not import another page. A hook (`use*`) holds data, state or a flow and returns no markup. A container calls hooks and renders one component tree. A component renders UI from props, keeps only local UI state and does not call `api/`, `platform/`, flags or navigation. A layout in `components/layout/` places the header, content and bottom areas and does not fetch data.
  - Folders (§2.2): the router, the route table with meta and the providers go to `app/`. Each route has `pages/<Route>/` with its page and the `hooks/`, `components/` and `containers/` that only this page uses. Code that 2 or more pages use goes to `containers/`, `components/ui/`, `components/layout/` or `components/<domain>/`. Server calls go to `api/client/` and `api/<domain>/`, and app services go to `platform/<area>/` (auth, session, settings, flags, navigation, device, storage, bootstrap, feedback). Pure functions go to `lib/`, and the OutSystems compatibility code goes to `legacy/os/`, which gets smaller in each phase. `mocks/` stays unchanged, and `styles/` holds the tokens and the CSS layers.
  - Container criterion (§2.3, R2 b): hooks by default. Make a container only in two cases. First, one component tree renders data from two different sources. Second, the tree needs 2 or more data hooks and 3 or more event handlers, in a file of more than 200 lines. The column `shape` of `app/docs/refactor/move-map.csv` records the choice for each block.
  - Rules 1 and 2 (§2.4): new code starts in `pages/<Route>/`. When a second page needs the code, the code moves to `components/`, `containers/` or `api/`.
  - Rules 3 to 9 (§2.4, import direction): a page does not import another page, and only `pages/<Route>/` imports `pages/<Route>/` (P3-1, dependency-cruiser rule `pages-imported-by-own-route-only`). `shared/` does not import `screens/` or `app/` (rule `shared-no-import-of-screens-or-app`). `components/**` does not import `api/`, `platform/`, `containers/`, `pages/` or `app/`, and `components/ui/` imports only `components/ui/`, `lib/` and `styles/`. `lib/` imports only `lib/`, and `api/<domain>/` imports only `api/client/`, `lib/` and `legacy/os/`. `platform/**` does not import `pages/`, `components/`, `containers/` or `app/`. Only `platform/`, `api/` and `app/` import `legacy/os/`.
  - P3-2 (decision Q11, auto-accepted under the user's delegation, 2026-10-22): the three UBTConnect modules import in one direction: `shared/UBTConnect/`, then `shared/UBTConnect_Utils/`, then `shared/UBTConnectLibrary/` (rules `ubtconnect-library-no-import-of-utils-or-ubtconnect` and `ubtconnect-utils-no-import-of-ubtconnect`). Exception: story files (`*.stories.tsx`) and test files (`*.test.ts`, `*.test.tsx`) are outside the cycle rule and every folder rule in `app/.dependency-cruiser.cjs` (constant `STORY_OR_TEST`). Reason: the cycle came only from 8 UBTConnectLibrary stories. They render the real blocks of the captured screen (for example BottomBarMenu), and Storybook is a review tool that must show them. Production code keeps every rule.
  - P3-3: three more rules keep cleaned directions in production code: `shared/osui/` imports no other `shared/` folder except `shared/lib/` (`osui-no-import-of-app-modules`), `shared/Connect2_LegacyShared/` does not import `shared/UBTConnect/` (`legacyshared-no-import-of-ubtconnect`), and `shared/Connect2_MyBookmarks_MUI/` does not import `shared/Connect2_Assemble_MUI/` (`mybookmarks-no-import-of-assemble`). All three are warnings and use `STORY_OR_TEST`. The only module cycle in `src/` (`platform/session/cachedUserInfo.ts` and `mockUser.ts`) is gone: the record type is in `platform/session/types.ts`.
  - P4-1: `platform/settings` is the typed store of the server settings that `synchAppContext` writes. It has 11 settings, one more than plan §3.2 (`pin.inactivity.navigate`). The OutSystems names stay in the adapter `legacy/os/clientVarNames.ts`, which `getClientVar` and `setClientVar` use until the readers move with their pages.
  - Rules 10 and 11 (§2.4): no import cycle anywhere. Imports use the alias `@/`, not `../../..`. Since P1-4, ESLint reports a relative parent import as an error (`app/eslint.config.js`). `src/sw` is exempt. In `components/**` the pattern stays a warning, because rule 4 shares it.
  - Rule 12 (§2.4, R8 b): a barrel `index.ts` exists only at `components/ui`, `components/<domain>`, `containers`, `api/<domain>` and `platform/<area>`. Other code imports these folders through the barrel only.
  - Rule 13 (§2.4, R4 b): each file that ports an OutSystems screen or block has one `@origin` tag. Inline references to compiled line numbers (`mvc.js:640-1150`) go away when the file is rewritten, not before.
  - Naming and OutSystems blocks (§2.5, §2.6): business names in PascalCase without a module prefix, and hooks named `use<Thing>`. Each `api/<domain>/` has `repository.ts`, `mapper.ts`, `keys.ts`, `hooks.ts` and `types.ts`; wire types stay in `src/api/schema.d.ts`. A UI-only block becomes a component, and a block with data or side effects becomes a hook and a component. A screen becomes `pages/<S>/<S>Page.tsx`, a layout block goes to `components/layout/` and an OutSystems UI pattern goes to `components/ui/`.
  - State (§2.7): TanStack Query is the only server-state store, and every call goes through `api/<domain>/`. Query options in `api/<domain>/keys.ts` replace `memoryCache`, after an exemption list (§5.4). View state moves to `platform/navigation/viewState.ts`; pages and hooks use it, and components do not. Client variables split into `platform/settings`, `platform/session` and `platform/navigation`.
  - Styles (§2.8, R3 b): Phase 8 adds `styles/tokens.css` and puts the original CSS in `@layer legacy`. Existing components keep the legacy class names and CSS, and new components use CSS Modules with the tokens. Unused CSS goes away one stylesheet at a time, with coverage data from the parity captures, at the `visual` level.
  - Feature flags (§3.1, R5 a): the `platform/flags` area has a typed registry, `resolveFlags` (precedence default < server < override) and `useFlag`. Only pages, hooks and containers read flags. The route table (`meta.flagRedirect`) handles the four flags that choose a screen. The app start waits for `fetchFlags()`. In production the flags come from one batch call through the BFF, with a parity exemption for the flag calls.
  - Session and PIN (§3.2, R6 a): a state machine in `platform/session/machine.ts` holds the session status, and the selectors keep their names. The `AuthProvider` interface in `platform/auth/` has the `mockAuth` implementation behind `MOCKS_BUILT`, and this refactor does not build `bffAuth`. The route meta (`access`, `lock`, `flagRedirect`) and `RouteGuard` keep the redirect table of `startup.ts` unchanged. The app start steps keep their calls, order and conditions, and `fetchFlags` is the only new step. PIN verification stays local, as in the original, and the security owner reviews it before the BFF phase.
  - Parity and API (§4.1, D1, D2): two parity levels, `strict` (all checks) and `visual` (no DOM checks), plus a self-parity reference. The API contract stays unchanged behind `api/<domain>/`.
  - Scope and sequence (R1 b, R7 b): phases 0 to 7 in about 50 days, and phases 8 and 9 as a stretch goal. Phase 2 builds a walking skeleton on HouseholdDetails before the mass work.
  - Tools (§4.4, D3 as changed by Q2 and Q4): dependency-cruiser checks rules 3 to 10 and exports the import graph. ESLint core `no-restricted-imports` checks rule 11. jscpd reports duplicate code, and knip reports unused files and exports. ts-morph runs the codemod `migration/tools/refactor/move.ts`.
