## Deviations from the brief
- Loader: the brief allows "`@import url(...) layer(legacy)` or an equivalent". I put the `@import` in a `data:` stylesheet behind a `<link>`, not in a `<style>`, for three reasons. (a) `parity_check.cjs` builds the outsystems reference page from the app's `link[rel=stylesheet]` hrefs only. With `<style>` imports, that page would get no original CSS. (b) `--preload-fonts` reacts to `load` events on `LINK` elements. (c) The link's `load` event fires only after the import has loaded, so StylesheetHost's first-render wait still works. The links carry `data-legacy-css="<file>"`. Production note: a future Content-Security-Policy must allow `style-src data:`. The other option is to serve one small wrapper file per original file. There is no CSP in the repo today.
- The order of the layers is set once, in `styles/layers.css`. It is the first CSS import of main.tsx and of the Storybook preview.
- Token layer: tokens.css is in `@layer app`, as the plan says for new CSS. Every token equals the legacy `:root` value on every screen, so the rendering is unchanged, and `tokens.test.ts` keeps it that way. Prettier lowercases hex colors, so for example the computed value of `--color-cyan-dark` on `:root` is now `#00819c`, not `#00819C`. The color is the same, and no app code reads token variables.
- Outside the 52 files I also changed `barcodePluginCss.ts` (into `@layer legacy`, to keep the original cascade) and `review.css` (into `@layer app`). Both changes are explained above.
- Storybook: `css_sets.py` now writes the HomeFeed set as `<style>@import url(...) layer(legacy)</style>`.
